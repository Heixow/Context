# Agent Context Visualizer — 需求基线

桌面端对话级 Agent：看清模型真实收到的上下文，由人主观决定保留什么，并让这些决定在后续对话中自动匹配生效。
状态：设计阶段。本文只定义需求与不变量，不规定实现方式。

## 1. 定位

核心主张：模型看到的不等于聊天记录。本工具观察实际发出的请求体（system + messages + tools），让人对这个请求体做减法，并让减法在后续轮次自动生效。
价值是「控制模型看到什么」在有 prompt caching 的现实中，删除中间消息会使后续前缀缓存失效，净成本可能上升；token 仅作为观测指标呈现，不作为收益承诺。本工具要解决的是上下文污染、注意力稀释、超限规避与语义依赖的显式管理。

## 2. 核心概念

| 概念 | 含义 |
|---|---|
| 帧 | 一次请求的完整上下文快照：system、messages、tools、usage |
| 会话 | 帧的有序集合；对话模式自动成会话，代理捕获的帧由用户手动合并 |
| 消息指纹 | 忽略元字段后对 role + 内容计算的稳定哈希，用于识别「同一条消息」 |
| 标注 | 用户对消息的主观决定，稀疏存储，默认保留 |
| 有效选择 | 会话内当前帧及之前所有标注的合并结果，后写覆盖前写 |
| 自动匹配 | 发送前按指纹应用有效选择，命中丢弃的消息被移除 |
| 种子 | 过滤后的完整请求体，可直接重放一次请求 |

## 3. 功能需求

### 3.1 观测

- 对话模式：应用即聊天客户端，用户接入自己的模型 API；每轮发送前捕获真实请求体并自动归入当前会话。
- 代理模式：本地反向代理，外部客户端指向它即可被动捕获同样的请求体；捕获必须 fail-open，不影响转发结果。
- 两种模式共享同一套概念、界面与导出能力。

### 3.2 可视化

- system 与 tools 定义完整可见；消息按块展示（文本、工具调用、工具结果）。
- 展示逐条 token 分布与总量；逐条为估算，总量以 API 返回的 usage 为准。
- 双数据源：实际请求捕获为主；本地 transcript 为备，并明确标注「可能已被压缩，非模型真实所见」。

### 3.3 主观精炼

- 逐条切换保留 / 丢弃，默认保留；实时派生保留量与总量。
- system 与 tools 恒保留，不参与选择。
- 选择只做减法，显式保留仅用于反悔。

### 3.4 自动匹配

- 发送前按消息指纹，将同一会话内的有效选择应用到当前上下文。
- 两种策略可切换：**自动生效**（直接移除命中项）与 **仅建议**（高亮待移除项，用户确认后发送）。
- 只作用于 messages，不跨会话继承。

### 3.5 导出

- 导出过滤后的完整请求体（可重放）与人类可读的上下文快照。
- 导出前必须通过结构校验。

## 4. 规则与不变量

1. 密钥与凭证绝不写入捕获文件或日志，仅用于向上游认证。
2. 代理 fail-open：捕获、解析、落盘的任何异常都不得改变上游响应，SSE 不得缓冲或改写。
3. system 与 tools 恒保留。
4. 发送与导出前必须通过结构校验：工具调用与结果成对；移除一方必须移除另一方；不得产生非法角色交替或空消息。校验只保证结构合法，不保证语义完整。
5. 自动匹配只作用于 messages，且只作用于同一会话。
6. 全程本地运行，不上传上下文数据；本地服务仅监听本机回环地址。
7. 逐条 token 为估算值，精确值以 API usage 为准。

## 5. 非目标与已知限制

- 指纹对压缩/改写敏感：历史被 compaction 改写后，旧标注不再命中。
- 消息级粒度无法只丢工具结果而保留同条消息中的用户文本。
- 内容完全相同的多条消息会产生相同指纹，存在误匹配风险。
- 自动生效可能误删有语义依赖的消息，重要场景建议用「仅建议」。
- 捕获数量上限淘汰帧时，须保证已做出的标注不因此静默失效。
- 跨会话不继承标注；暂不支持子代理会话、暂不支持从历史会话回灌。
- 不做实时请求改写：自动匹配只发生在应用自身的发送链路上。

## 6. 路线图

| 阶段 | 内容 |
|---|---|
| P0 | 对话模式：接入、可视化、逐条精炼、指纹自动匹配、导出。机制须可在代理帧上复用 |
| P1 | 代理模式：外部捕获、手动合并会话、双数据源浏览 |
| P2 | 可解释的规则匹配（按工具/位置），再考虑语义相似匹配 |
| P3 | 实时干预：请求发出前按用户规则改写上下文 |
